# Take MGM Agent for a spin

[Français](#français) · [Download for Windows](INSTALLATION.md#english) · [Open MGM Agent](https://agent-ia.mgminformatique.ca)

**Bring a task. Leave with something you can check.** Start with the fictional
notes below, then try your own project. An MGM account and an eligible plan
are required; requests use your available points. MGM Work requires Windows
and Ultra.

## 1. Turn rough notes into a usable guide

Open a new **Chat**, choose an available model and paste this complete example:

```text
Turn these fictional project notes into a short onboarding guide in Markdown.
Use four sections: Goal, Prerequisites, Steps, Final checks.
Do not invent missing details. Finish with the questions still to answer.

Notes:
- Project: a neighborhood repair workshop.
- Visitors book a 30-minute slot by email.
- Bring the broken item and its power cable, if applicable.
- A volunteer checks whether the item can be repaired before work begins.
- The opening hours, address and contact email have not been decided.
- Repairs are not guaranteed.
```

**Check the result:** the booking process, what to bring and the initial
assessment should appear in the guide. Hours, address and contact email
should remain open questions. You now have a concrete draft to improve or save.

## 2. Go from a chat to files in MGM Work

With Ultra, open **MGM Work**, select MGM's agent and choose a new, empty folder
for the exercise. Paste the same notes, followed by:

```text
Create ONBOARDING.md from these notes and CHECKLIST.md with the volunteer's
arrival checklist. Only create these two files in the selected folder.
Keep the missing details visible. Read both files back before reporting the
result, and tell me which checks you actually completed.
```

Review any requested approval before allowing a local action.

**Check the result:** open both files in your editor. Confirm the guide matches
the notes, the checklist is usable and neither file invents contact details.
Check both the existence of the files and their contents.

## 3. Add a requirement while work is happening

On a fresh copy of the file exercise, send this follow-up while the agent is
working, or as the next message if it has already finished:

```text
Also add a French version named ACCUEIL.md. Keep the two original files.
Use the same facts and open questions in both languages. Verify all three
files before you finish.
```

After the task finishes, return to the conversation or reload it.

**Check the result:** all three files should exist. The added instruction and
earlier results should remain in the saved conversation. A pending approval or
incomplete item should remain visible. This exercise evaluates continuity on
your setup; it does not guarantee every model's output.

## Show what worked

Share the **task, model, app version, expected result and observed result** in
[Discussions](https://github.com/mgminformatique/mgm-agent-public/discussions).
A small example helps the next person get started. For a reproducible failure,
use the [bug report form](https://github.com/mgminformatique/mgm-agent-public/issues/new?template=bug_report.yml).
Use fictional or shareable material in public examples.

## Français

**Une tâche concrète. Un résultat que vous pouvez vérifier.** Commencez avec
les notes fictives ci-dessous, puis passez à vos propres projets.
Un compte MGM et un forfait adapté sont nécessaires ; les demandes utilisent
vos points disponibles. MGM Work nécessite Windows et Ultra.

### 1. Transformer des notes en guide

Dans un nouveau **Chat**, choisissez un modèle disponible et collez cet exemple :

```text
Transforme ces notes fictives en petit guide d'accueil au format Markdown.
Utilise quatre sections : Objectif, Prérequis, Étapes, Vérifications finales.
N'invente aucune information manquante. Termine par les questions à résoudre.

Notes :
- Projet : un atelier de réparation de quartier.
- Les visiteurs réservent un créneau de 30 minutes par courriel.
- Apporter l'objet en panne et son câble d'alimentation, s'il en a un.
- Un bénévole vérifie si l'objet est réparable avant de commencer.
- Les horaires, l'adresse et le courriel de contact ne sont pas encore décidés.
- La réparation n'est pas garantie.
```

**À vérifier :** la réservation, le matériel à apporter et l'évaluation initiale
figurent dans le guide. Les horaires, l'adresse et le courriel restent des
questions ouvertes. Vous avez un premier document à améliorer et à conserver.

### 2. Passer aux fichiers dans MGM Work

Avec Ultra, ouvrez **MGM Work**, choisissez l'agent MGM et sélectionnez un
nouveau dossier vide pour l'exercice. Collez les mêmes notes, puis ajoutez :

```text
Crée ACCUEIL.md à partir de ces notes et CHECKLIST.md pour l'accueil par les
bénévoles. Crée uniquement ces deux fichiers dans le dossier sélectionné.
Garde les informations manquantes visibles. Relis les deux fichiers avant de
terminer et indique les vérifications que tu as réellement effectuées.
```

Examinez les demandes d'approbation avant d'autoriser une action locale.

**À vérifier :** ouvrez les deux fichiers dans votre éditeur. Le guide respecte
les notes, la liste est utilisable et aucune coordonnée n'a été inventée.
Vérifiez l'existence des fichiers et leur contenu.

### 3. Ajouter une consigne en cours de travail

Sur une nouvelle copie de l'exercice, envoyez cette précision pendant le
travail, ou dans le message suivant s'il est déjà terminé :

```text
Ajoute aussi une version anglaise nommée ONBOARDING.md. Conserve les deux
fichiers d'origine. Les faits et les questions ouvertes doivent rester les
mêmes dans les deux langues. Vérifie les trois fichiers avant de terminer.
```

Une fois le travail terminé, revenez dans la conversation ou rechargez-la.

**À vérifier :** les trois fichiers existent. La précision et les résultats
précédents restent dans l'historique. Une approbation en attente ou un élément
incomplet doit rester visible. Cet exercice évalue la continuité sur votre
installation ; il ne garantit pas la réponse de chaque modèle.
